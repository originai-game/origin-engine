# Crates the wasm step builds with
#   cargo build --release --target wasm32-unknown-unknown -p <crate> --lib
# One "crate status" pair per line; '#' starts a comment.
#   required  built together in one cargo invocation; a build failure fails the gate
#   pending   built one at a time; a build failure prints WARN and is tolerated
#             (use while a crate is being ported; flip to required once it builds)
# A crate without a cdylib crate-type builds but yields no .wasm; that is
# reported, not failed, until budgets.txt says `wasm_artifacts required`.
# A third word `publish` builds the crate a second time with its `publish`
# feature (the shipping variant: what the size gate measures and what
# build.sh puts in dist/web-publish).
# A fourth word `lanes` builds the publish variant a third time with wasm
# atomics through scripts/wasm-lanes.sh (the lanes variant, out-name
# origin-engine-lanes: docs/web-export.md §Lanes); the size gate measures it
# as its own download.
# A line `variant NAME CRATE FEATURES` replaces the crate's one publish
# variant with one per line: built with --no-default-features --features
# FEATURES (comma-separated, the crate's own) into target/wasm-NAME, raw
# name <crate>-NAME.wasm. og-host-web ships one per game profile, each with
# only its profile's physics (docs/web-export.md §Variants): `publish` is
# the 3D variant (dist/web-publish) and `publish2d` the 2D one
# (dist/web-publish-2d); `og build --publish` copies the one of the game's
# profile. Both keep og-ui's `shaping` (rustybuzz: Arabic, Indic). The lanes variant keeps the publish features with both
# profiles. The size gate holds each download to the budget.
og-render   required
og-host-web required publish lanes
variant publish   og-host-web publish,physics3d,shaping
variant publish2d og-host-web publish,physics2d,shaping
