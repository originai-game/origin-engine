# UI catalogue

`catalogue.json` is generated by `og api gen` and checked by `og api check`.
Do not edit entries. Built-in component and pattern documentation and parameter
names come from the IDL; screen purposes come from their document headers;
kits and styles come from `extension.json`. A kit's registered public functions
and their descriptor documentation supply its component entries. Adding a kit
following the existing `registerUiExtension` pattern requires no catalogue edit.

These are starting points to restyle, not finished game UI. Keep input,
localization and behaviour; change typography, palette, spacing, hierarchy and
art for the game. Call examples show parameter names: use `og api show` and the
entry's source for their types and fixture values.

## Search contract

`og ui find <query> [--json] [--project DIR]` reads the selected engine package,
without executing game or extension code. All whitespace-separated words must
match its name, kind, purpose, genre or kit, case-insensitively. Exact names come
first, then stable IDs in lexical order. `--json` prints an array of full entries
and no prose. No matches is `[]` and exit 0; a missing/bad catalogue or invalid
arguments exits 1. A blank query is an error.

The file has `format: 1`, `guidance`, and `entries`. Each entry has `id`
(`kind/name`), `name`, `kind`, `purpose`, `genres`, `example`, nullable `kit` and
`pack`, `install`, `source`, `thumbnail`, and `guidance`. `any` means the mechanic
is not restricted to a genre, not that its sample styling fits every game.
The knowledge mount copies the JSON to
`game/skills/og-ui/catalogue/catalogue.json`. Images stay in the engine package,
outside the platform's text-only knowledge mount.

## Art-runner thumbnails

From an engine checkout with a built native addon and `target/debug/og`:

```sh
bun scripts/render-ui-catalogue.ts --plan
bun scripts/render-ui-catalogue.ts --render
# Or one entry, with output outside the committed package:
bun scripts/render-ui-catalogue.ts --render --only component/pushButton --out .amp/in/artifacts/catalogue
```

The renderer uses the existing kit/style sheets, the ui-kit's pack-ground mode,
the screen documents' default fixtures, and isolated fixtures for components
not directly called on those pages. Each batch acquires a GPU slot through
`scripts/lock.sh`. No 3D scene or key art is added behind UI. Thumbnails are
written to the entry's path relative to this directory. `render-report.json`
names captures and missing fixtures; a missing capture fails instead of
substituting a generic card or another component's art. Read the images before
adding them: generation is not art approval. Thumbnail pixels are deliberately
not part of API drift checking.

The fallback icon sheet is `og ui sheet development-fallback-icons`: ten groups,
at 16, 24 and 40 px and inline in rich text, on a plain ground. Run it under a
GPU slot too. The set's `icons.json.developmentFallback` and its asset path are
the identifiers for the later publish refusal, not an exemption from it.
