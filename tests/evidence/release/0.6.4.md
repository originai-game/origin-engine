# Release 0.6.4 (2026-10-27 UTC)

All five npm packages are published at 0.6.4, and `latest` points to 0.6.4.
Tag `v0.6.4` (annotated, "Origin Engine 0.6.4") is pushed at
`397dbc7966f3a19cbd6ed4b19a9a63792f8340c8`, the commit `release.yml` run
40518421225 checked out.

This is a patch release (docs/release.md §3) with the simulation
**unchanged** and no IDL member changed. It adds one tool command:

- `og bake projection` (`init`, `plan`, `prepare`, `project`, `holes`,
  `export --run <dir>`): a gray level glb painted from planned views by an
  image model the caller runs, projected into one texture and exported as a
  textured glb, on the CPU (docs/design.md §Projection painting). A level
  without uvs is charted with xatlas.

`changelog.json` records 0.6.4 as a patch with simulation `unchanged`, no
breaking entries, one added line and no fixed lines.

## Verification

| Where | From the tarballs | From the registry | Doctor renderer |

The orb ran its own docker daemon for this release (`sudo dockerd` as an orb
service), so the container pass ran here rather than on macrunner.

The macrunner (darwin-arm64, Metal) and studio-win (win32-x64, DX12) checks,
from the tarballs and from the registry, were not run for this patch and
were not required: the change adds a CPU-side `og` command, leaves the
simulation and the IDL unchanged.

npm's staged publishing held the packages for 2 to 28 minutes after the
publish at about 14:35Z. engine-darwin-arm64 and engine-linux-x64 were
served within two minutes, and engine-win32-x64 and create-game within
about seven. `@origingame/engine` was served only at 15:03:22Z. Its sha1
`f01f0e02…` matches the local tarball. At 14:47Z a second
`release.sh publish` skipped the four served packages (the same bytes) and
got "409 Cannot publish over previously staged version" for
`@origingame/engine`, which confirms the first upload was accepted. For
those 28 minutes create-game@0.6.4 was `latest` while the engine it pins
was not served, so `npm create @origingame/game` could not install. The
registry checks started only after all five tarballs returned 200.

og-runtime's `stream_chunked` and `stream_fetch` tests are intermittently
flaky, on 0.6.3 as well; that is not a change of this release.

InstaBox and the phone checks were not part of this run.
