# Release 0.7.0 (2026-10-28 UTC)

All five npm packages are published at 0.7.0, and `latest` points to 0.7.0.
Tag `v0.7.0` is pushed at `7757383a6409c9defe8c5a8a3db79f1177d756d6`, the
commit `release.yml` run 40655069009 checked out.

This is a minor release (docs/release.md §3) with the simulation
**unchanged**. It is the art wave (docs/art.md, streams A1–A7):

- The art contract: seven look resources (`ArtPalette`, `ArtPixels`,
  `ArtTexels`, `ArtShape`, `ArtLine`, `ArtMotion` and `ArtCamera`), and
  `project.ogt`'s `look` line.
- The cook's 2D and 3D conformance.
- The runtime defaults: sprite outline, palette swap, cleanEdge sampling,
  and the camera and motion defaults.
- `artBrief`, `readLook` and `presetLook`.
- `og style check`.
- The family sample scenes `examples/art-<family>`.

`changelog.json` records 1 breaking entry, 30 added lines and no fixed
lines. The breaking change: a project whose look sets the art blocks now
cooks and draws its assets to them. A project without a look, or with no
art block set, draws as before.

On studio-win the first attempt passed the addon as `OG_ADDON`. The loader
reads `OG_NATIVE_ADDON`, so that attempt loaded a stale dev addon and
diverged. With `OG_NATIVE_ADDON` set to the tarball's addon, it passes 2/2.
The same slip affects the win32-x64 "release og and addon from the
tarball" rows of the 0.6.5 and 0.6.6 receipts. Those runs used the
tarball's `og.exe` with the stale dev addon built at `91e5a2ff`, so their
Windows tarball-addon replays are **unverified**. By the coordinator's
decision they are not rerun: 0.7.0 supersedes both, and its Windows replay
passes 2/2 with `OG_NATIVE_ADDON`.
