## npm's staged publishing

npm 11.16 publishes a new package in two steps: a stub `0.0.0-stage`
version, then the real one once the two-factor prompt is answered. Three
packages went through; `@origingame/engine-darwin-arm64@0.1.0` stayed
staged and invisible for about ten minutes (`npm stage list` showed
nothing, a second `npm publish` was refused with E409 "Cannot publish over
previously staged version"), then appeared on its own; its tarball on the
CDN followed the metadata by a few more minutes (a `bun install` in
between resolved the version and got 404 on the tarball, so the optional
platform package was silently skipped). Each package keeps its
`0.0.0-stage` stub as a published version; `latest` is `0.1.0`
everywhere. For the next release: after `publish`, wait for `verify
--registry` to pass before announcing the version.
