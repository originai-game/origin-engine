# Release 0.4.0 (2026-10-24)

Prepared from clean `fba63701` on macrunner. This is a minor release for
the API additions since 0.3.0; CHANGELOG.md lists them. All five packages
are published on npm with `latest` set to 0.4.0. Their registry shasums
match the candidate tarballs. The local release tag is `v0.4.0`; neither
the engine branch nor tag has been pushed in this release round.

## Registry checks

`scripts/release.sh verify --registry` passed on darwin-arm64 (81.4 s,
Metal) and linux-x64 (51.5 s, container without a renderer), 137.6 s
overall. Initial attempts preceded registry propagation; a fresh Bun
cache avoided retaining the old version metadata. Log:
`.amp/in/release-0.4.0-registry.log`. Windows registry verification is
still pending; its exact candidate verification below passed.

## F7: real Windows thread, published engine 0.3.0

After the authorized Identity delegation fix and Agent Service LFS fix,
thread `T-08519944-165d-4dc6-86bf-0e90b9e41cbb` completed on a fresh
registered Windows runner (runner 0.1.4, engine 0.3.0). Scaffold, start,
probe, capture at tick 464, edit, reload with world preserved, capture
at tick 1985 and stop succeeded. Its branch was pushed; a fresh Mac clone
contained the edit and eight LFS objects, with `git lfs fsck` passing.
The Windows worker inspected both captures and reported normal scene
and HUD rendering. This closes F7; it is not a real-thread test of 0.4.0.

Earlier attempts exposed missing runner `OG_ENGINE_PACKAGE` configuration
and duplicate LFS verify Authorization headers, not a Windows byte-format
problem. The deployed Agent Service fix removed the duplicate credential
and retained both extraHeader and credential-helper authentication.

Both runner registrations were deleted and test repositories archived.
The loopback-only SSH tunnels were closed; both hosts removed tokens.
Windows also removed runner-data and checkout and confirmed no remaining
runner/og.exe process or listener on 9511. No SSH key was copied.
