# Release 0.6.2 (2026-10-27 UTC)

All five npm packages are published at 0.6.2, and `latest` points to 0.6.2.
Tag `v0.6.2` is pushed at `495663919b94c8b41d67bccce4ccc670b66472fa`, the
commit `release.yml` run 40480780706 checked out. The registry's SHA-512
integrity matches every tarball below.

This is a patch release (docs/release.md §3). It ships the engine side of the
version policy:

- `packages/engine/changelog.json`;
- `og upgrade`;
- `og doctor --json` with its `pin`;
- `og replay record` and `og replay compare`;
- the golden-replay patch gate (`scripts/replay-gate.ts`, run by
  `release.sh bump`).

It also includes `50f53b97`, which makes `og replay`'s bundle hash leave the
engine path out on Windows. `changelog.json` records it as a patch with the
simulation unchanged and no breaking entries.

  - fx-showcase passes 5/5 in Chrome 155.0.8059.41 and Edge 155.0.4283.45,
    on both WebGPU and WebGL2.
- **orb** (`49566391`): the functional lane passes, with nextest 1398/1398.

In a demo installed from the tarballs on all three platforms:

- `og doctor --json` gives `ok: true` with
  `pin: {"pinned":"0.6.2","installed":"0.6.2","compatible":true}`.
- `og upgrade --dry-run --json` gives `status: done` and `kind: none`, with
  no codemods and no manual edits.

The first Windows tarball run failed in `og test` intro at tick 480, with
"the renderer produced no frame". Diablo IV was running in the host's
interactive session and held about 5.8 GB of the RTX 5060's 8 GB. The 0.6.0
demo, which passed earlier, failed the same way under the same conditions.
After the game was closed (1385/8151 MiB in use), the test passed.

npm took a few minutes to show the new versions and serve the tarballs. The
registry checks started only after all five tarballs returned 200.

InstaBox and the phone checks were not part of this run.
