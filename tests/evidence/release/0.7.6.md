# Release 0.7.6 (2026-10-31 UTC)

All five npm packages are published at 0.7.6. Tag `v0.7.6` (annotated) is
pushed at `bff867c772149618851d33b88dd7a3eb258dad96`, the commit
`release.yml` run 41162236609 checked out.

This is a patch (docs/release.md §3) with the simulation **unchanged** and
no IDL member added or removed. The one change since 0.7.5:

- `65b20c02` og-cli: `og api find <words>` lists the API reference entries
  matching the words (name, module, first sentence, then field and parameter
  docs), one line each; `og api show <name>` prints one entry in full
  without its IDL source. Both read the wiki of the installed engine
  package (`knowledge/wiki`), so they answer for the version a game runs.
  og-core §7 and og-game §25 teach them.

`changelog.json` records 0.7.6 as `kind: patch`, simulation `unchanged`, no
breaking entries, one added line, from the `unreleased` block the change
wrote.

## Verification

| Where | From the tarballs | From the registry | Doctor renderer |
| --- | --- | --- | --- |
| Mac satellite darwin-arm64 (macos-27 VM, Metal, mac.medium) | PASS 49.9 s (third run; see below) | PASS 71.4 s | `ok metal` |
| orb linux-x64 container | PASS 43.9 s, frames unchecked | PASS 18.5 s, frames unchecked | `none` |

- The Mac satellite received the tarballs over a forwarded orb port; each
  sha256 equals the manifest's. Its pass was recorded in the orb's
  `manifest.json` as `verified.host`, and `publish` ran on the orb.
- On the fresh Mac VM the first two runs each failed once, at the same
  places as 0.7.5's: run 1 at the runner archetype's `flow` suite (53 s,
  "the renderer produced no frame" at tick 18; its frames still matched),
  run 2 at the 2D starter's first suite (14 s; the runner passed this time).
  Run 3 passed every step, and the registry run passed first time. This is
  the VM's one-time Metal pipeline compile recorded with 0.7.5, not a 0.7.6
  change (0.7.6 changes no runtime code).
- **`og api` on the released og.** In a fresh project outside any checkout
  with `OG_WIKI_DIR` unset, `og api show og.CharacterController` printed the
  component's entry (3,880 B, ending `(og.CharacterController · record;
  page physics.md)`), and `og api find character controller` ranked
  `og.CharacterController` first, then `og.CharacterEvent` and
  `og.PlatformerController`. Same output from the tarballs (linux-x64) and
  from the registry (linux-x64 and darwin-arm64). With the package's
  `knowledge/wiki` moved aside, `og api show` failed with "no API reference
  found", so the answer came from the installed package's wiki.
