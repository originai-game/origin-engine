# Release 0.1.1 (2026-10-22)

A patch of 0.1.0 found by the platform's L stage (docs/release.md §4 L3):
npm drops `.gitignore` from every tarball, so a scaffolded game, the
archetypes and the knowledge's scaffold overlay had none (the runner's
scaffold test failed on "cooked/ is ignored"). The packages store it as
`gitignore`; `create-game`, the knowledge mount and the runner's
`engine_scaffold` write it back as `.gitignore`, as `gitattributes` already
was. The install test checks both files in the scaffolded projects. No API
change (CHANGELOG.md).

Packed from 887c3378 (`dist/release/0.1.1/manifest.json`; the tag `v0.1.1`
marks 142078d3, the docs commit at which the owner published), verified from
the tarballs on darwin-arm64 and in the linux-x64 container before the
publish, and from the registry after it:

| Platform | From the registry | Notes |
|---|---|---|
| darwin-arm64 (M4 Pro) | PASS, 62.6 s | `metal`; `.gitignore` and `.gitattributes` in the demo and the runner scaffold |
| linux-x64 (node 22 + bun 1.4.2, no GPU) | PASS, 42.4 s | renderer `none`, frames unchecked and said so |

The publish itself: npm's registry answered 503 three times on
`create-game`'s upload (the three other packages went through at 202);
`scripts/release.sh publish` run again skipped them by integrity and
published it. Every package's `dist.integrity` equals the local tarball's.

The platform's side of this version: origingame
`goals/origin-engine/evidence/pin-0.1.1.md` (the layout from the packages on
both targets, the knowledge mount with `--check` clean against the registry,
the runner's `og` tests, `stage-engine` 12 of 12, `engine-page.ts` on a real
Portal).
