# What Hollowbell found

Every problem met writing this game from the knowledge package (skills and wiki) and the generated types as a game author would, in the order met. Nothing in the engine was changed; each workaround is named, and the code carries it with a comment naming the finding's number. Engine source was read only to confirm a suspected bug after it was hit (#6, #9, #16 say so). Ratings: **blocker** (the documented way does not work), **annoyance** (costs real time, or silently wrong), **nit** (small, cosmetic, docs only). Engine 5e50479f (main, after wave 7, so lantern-vale's 32 findings, fixed there, are not repeated); dev-profile `og` and addon; tier metal. Commands run from the repository root, `og` = `target/debug/og`.

| | Blocker | Annoyance | Nit | Total |
|---|---|---|---|---|
| Count | 3 | 10 | 7 | 20 |

Top five: #9, #16, #6, #1, #11 (with #12).

1. **There is no game-side world snapshot to save a slot with** — annoyance (API gap). Every module page says "snapshots, restore and the world hash cover it" and og-ui §1 says "snapshots and replays carry it", so an author reaches for a snapshot to save progress; the only one is `EngineProbe.snapshot`/`restore` (wiki/probe.md), a probe member kept in the running process and dropped in publish builds, and the command channel has no `snapshot` action. Repro: `grep -n "snapshot" packages/engine/types/index.d.ts` (only `EngineProbe.snapshot` and `SnapshotInfo`). Workaround: `src/save.ts` writes the run as a JSON record to `og.platform`'s store (`save`, at the revision read, a conflict read again and rewritten) and Continue rebuilds the world from it; `tests/save.og.ts` proves it across a relaunch.
2. **The tileset and Tiled grammar are not in the knowledge package** — annoyance (docs). og-game §8 lists what a `type tileset` holds (grid, solid, collide rects, animated tiles, terrain rules) and that Tiled maps load, but no skill or wiki page gives the `.ogt` lines (`grid 16 16 8 9`, `solid ...`, `tile <id> { frames fps }`, `terrain <name> { mode blob47 rule <mask> <tile> default edge filled }`), how a `.tmj`'s `../tiles/x.tsx` reference resolves to `tiles/x.ogt`, or which Tiled layer properties the cook reads (`autotile`, `collision`, `z`, `repeat`; Tiled's own `parallaxx`/`parallaxy` turned out to work). Repro: `grep -rn "autotile\|blob47\|parallaxx" packages/knowledge` finds nothing. Workaround: copied the grammar from `templates/archetypes/topdown/tools/make-assets.py` and its `tiles/dungeon.ogt`; `repeat` and the parallax fields confirmed by `og.load.tilemap`'s `TileLayerInfo` and a frame.
3. **The particles grammar page the docs point to does not exist** — annoyance (docs). `og.load.emitter` (wiki/load.md) says "the grammar is the `particles` page of the wiki's render module and og-cook's fx module"; there is no such page in `packages/knowledge/wiki/`, and og-game §10 only says "rate, bursts, lifetime, speed, curves, collision". Repro: `ls packages/knowledge/wiki | grep -i particle` (none). Workaround: copied the lines from `templates/archetypes/idle/assets/fx/*.ogt` and lantern-vale's `fx/burst.ogt` (`shape`, `spread`, `burst`, `looping`, `sizeOverLife`, `colorOverLife { key ... }`, `array "<id>" random`, `render sprite <layer>`).
4. **og-i18n §3 sends a Japanese game to a Noto Sans JP subset the engine does not have** — nit. It names `templates/ui-kit/tools/make-locale-fonts.py`, but the only JP font in the repository, `templates/ui-kit/assets/fonts/NotoSansJP-subset.otf`, holds 177 glyphs (28 kanji), and the 2.5 MB `NotoSansSC-Regular-subset.ttf` lacks the Japanese forms of common kanji (鐘 鈴 険 続 設 語 楽 効). Repro: `python3 -c "from fontTools.ttLib import TTFont; c=TTFont('templates/game/assets/fonts/NotoSansSC-Regular-subset.ttf').getBestCmap(); print([x for x in '鐘鈴険続設語楽効' if ord(x) not in c])"`. Workaround: the second language is 简体中文, subset from the SC font by `tools/subset-font.py` (copied from lantern-vale).
5. **og.PlatformerController takes no velocity or impulse from the game** — nit (API gap). A knock-back (og-feel §3 pairs it with the hit stop) has no field to push the character: only `moveX`, `jump` and `down` go in, and `velocity` is written by the engine. Repro: `og.PlatformerController` in `packages/engine/types/index.d.ts` (`readonly velocity`). Workaround: `src/hero.ts` runs Wren away from the hit at full `moveX` for `Tuning.knockTicks` ticks without control (#5).
6. **BLOCKER: two `world.resource()` handles of one resource disagree: a handle caches every field when it is fetched.** wiki/world.md calls it "a resource's live value", but a handle's getters answer the values at fetch time (writes do go through, field by field). In `start`, `buildHollow` set `Game.spawnX` on its own handle and `start`'s earlier handle still read 0, so the new run warped Wren to the origin and Wren fell out of the map, with no error. Confirmed in `packages/engine/src/runtime.ts` (`liveResource`: `get: () => value[key]` over a copy). Repro (a 12-line game): `const a = must(world.resource(R)); const b = must(world.resource(R)); b.x = 5; console.log(a.x)` logs 0, while `get:R` shows x 5. Workaround: one handle per scope, passed down (`buildHollow(world, art, g)`, `spawnVoices(world, g)`, `touchHero(world, g, x)`; #6 in `src/world.ts`, `src/main.ts`, `src/enemies.ts`).
7. **A 240-line pixel grid falls back to 2x at 1280x720; `pixelUpscale 3` is ignored** — annoyance. 240 lines at 16:9 is 426.67 logical pixels wide, rounded up to 427, and 427 x 3 = 1281 does not fit 1280, so the frame is drawn at 2x (854 x 480) inside a 213-pixel border; setting `Stylise.pixelUpscale 3` changes nothing. The `16bit-pixel` preset's own 224 lines fit at 3x but leave a 24/43-pixel border at 720p. Repro: set `pixelHeight 240` in `examples/hollowbell/assets/looks/hollowbell.ogt`, then `og cook examples/hollowbell && og run examples/hollowbell --headless --commands "1:screenshot:g.png;1.1:quit"`. Workaround: the preset's 224 lines and a 14-cell view (16 px a cell), accepting the border.
8. **Screen sprites always draw under og.ui, whatever their layer** — nit. og-game §10 says `og.render.sprite` with `screen` draws "over the finished frame ... og.ui uses the same layer", without the order; a screen sprite at `layer: 1000` over a HUD capsule is hidden by the capsule. Repro: draw the HUD's chimes inside `capsule("Chimes", ...)` in `src/ui.ts` `hud` (the capsule's ground covers them). Workaround: the chimes' row has no frame; a screen-sprite backing and the chimes are drawn there (#8 in `src/ui.ts`).
9. **BLOCKER: og.Lighting2D never lights a tilemap.** wiki/render.md: "2D lighting of the sprite layers minLayer to maxLayer"; wiki/tilemap.md: "Layers draw through the sprite batch ... each at the map's sprite layer plus its z". With the map's layers inside the lit range and the ambient at 0.08, the rock and the back wall drew exactly as authored (pixel for pixel the same with lighting on and off) while sprites darkened, so a dark cave lit by torches cannot be made with the documented pieces. Confirmed in `crates/og-render/src/sprites.rs` `tile_instances` (every tile instance has `fx: [0.0, 0.0, 0.0]`: never lit). Repro: drop `MapShade` from the systems in `src/main.ts` and set `lighting.minLayer = -100` in `src/world.ts`, then `og run examples/hollowbell --headless --commands "0.3:play;0.4:warp:44:3;2:screenshot:a.png;2.1:set:og.Lighting2D.enabled=false;2.2:screenshot:b.png;2.3:quit"`: the map's pixels in a.png and b.png are equal. Workaround: `MapShade` tints the map with the area's ambient (`og.Tilemap.color`) and a soft additive light-pool sprite (`fx/pool.png`) sits under every light (`Pools`, #9 in `src/props.ts`, `src/world.ts`); the map takes no occluder shadows (sprites still do). `tests/lighting.og.ts` checks the pools in a frame.
10. **og.ui.cutscene does not take the focus when it opens** — annoyance. "A press or Activate while typing shows the whole line" (wiki/ui.md `og.ui.dialogue`) and og-ui §4 "the topmost owns focus", but with the talk open Enter, Space and the pad's A did nothing until Tab moved the focus onto its box, so a keyboard or pad player is stuck on the first line. Repro: remove the `og.ui.navigate(world, "next")` line in `src/ui.ts` `talk`, then `og run examples/hollowbell --headless --commands "0.3:play;0.4:warp:mole;1:key_down:ArrowUp;1.034:key_up:ArrowUp;1.5:key_down:Enter;1.534:key_up:Enter;1.8:key_down:Enter;1.834:key_up:Enter;2:get:Game.talkIndex;2.1:quit"` (0). Workaround: navigate the focus to the box while it is not there (#10 in `src/ui.ts`).
11. **og.ui.settingsScreen stays English in every locale** — annoyance. og-i18n §2 says each word of a template is a field of its desc with the English default, but `SettingsDesc` has none: in zh-CN the dialog read Settings, Audio, Graphics, Controls, Language, Master, Music, Effects, Mute everything, Done. Repro: call `og.ui.settingsScreen("Settings", { open: true, settings: {}, languages: [...] })` after `language:zh-CN` and `dump_ui`. Workaround: the settings are a modal of widgets with every string from the tables (#11 in `src/ui.ts` `settings`), which also keeps reduced motion and high contrast beside the language.
12. **og.ui.shopScreen's own words stay English** — annoyance. Price, Buy and Not enough (the disabled Buy) have no `ShopDesc` field, so the Chinese shop shows them in English beside Chinese wares. Repro: `og test examples/hollowbell` (`tests/locales.og.ts` asserts the English words are there, naming this finding). Workaround: none; the game keeps the template.
13. **og-game §13 says a kinematic body moves by its og.Velocity; it does not** — annoyance (docs disagree). "og.Velocity is optional: ... a kinematic body moves by it when it has one"; the lift (kinematic, `Velocity.linear.x` 2) stayed put, as `BODY_KINEMATIC`'s own doc says ("moved by game code through its Transform; its Velocity, if any, is how fast it pushes"). Repro: delete the `tr.position[i * 3] = x + ...` line in `src/props.ts` `Lifts`, then `og run examples/hollowbell --headless --commands "0.5:get:lift.og.Transform;1.5:get:lift.og.Transform;1.6:quit"` (both 24.5). Workaround: `Lifts` moves the Transform by the velocity and keeps the velocity, which the controller standing on it rides (#13 in `src/props.ts`; `tests/move.og.ts` checks the ride).
14. **An example in the engine repository cannot be type-checked as written** — nit. `tsconfig.json` (the template's, also lantern-vale's) resolves `@origingame/engine` from `node_modules`, which an example in the repository has none of, and `og` does not type-check; `tsc -p examples/hollowbell` fails on every import, and the knowledge package never mentions type-checking. Repro: `cd examples/hollowbell && npx tsc -p . --noEmit`. Workaround: a scratch tsconfig with `paths` to `packages/engine/types/index.d.ts` and `packages/engine/src/playtest.ts`; `src` and `tests` check clean that way.
15. **A PlatformerController put exactly on a tilemap's floor sinks 7 mm and cannot run sideways** — annoyance (bug). Written to the floor's height (a warp, a respawn, a continue, the probe's `teleport`), Wren sank to 15.993 at some places (x 26 and 40 of the upper floor; not at 20 or 60, not on a single box collider) and Right moved nothing until a jump. Repro: `og run examples/hollowbell --headless --commands "0.3:play;1.2:teleport:hero:26,16,0;1.6:key_down:ArrowRight;1.9:get:Game.heroX;2:quit"` (26.0). Workaround: every warp puts the feet 5 cm over the floor (`WARP_LIFT`, #15 in `src/ui.ts`, `src/hero.ts`).
16. **BLOCKER: og.PlatformerController's run stutters on flat ground.** Every few ticks its velocity drops to almost 0 and it accelerates again (1.17 m/s a tick at the default 70 m/s²), so the hero hitches and runs well under `maxSpeed`: on Hollowbell's upper floor one second of Right covers 4.7 m at `maxSpeed` 6.5, the velocity reading 6.5, 0.07, 2.4, 4.7, 0.19, 0.05, 2.4 two ticks apart. It happens on one flat box with every default, so it is not tile seams: a 20-line game (a 74 x 3 box floor, a 0.7 x 1.25 box with `og.PlatformerController {}`, `moveX` 1 every tick) logs about 30 drops in 2.3 s; a capsule, `skin` 0.03 to 0.15 and `snapDistance` 0 or 0.3 change how often, not whether. Read after hitting it: `crates/og-physics/src/platformer.rs` sets `vx = moved.translation.x / dt` whenever `move_shape` (rapier's `KinematicCharacterController` with `slide`, `crates/og-physics/src/ext.rs`) returns less x travel than asked, and it intermittently returns almost none while the shape grazes the floor. Repro: `og run examples/hollowbell --headless --commands "0.3:play;0.5:warp:11:16;1:key_down:ArrowRight;1.6:get:hero.og.PlatformerController.velocity;1.634:get:hero.og.PlatformerController.velocity;1.668:get:hero.og.PlatformerController.velocity;2:get:Game.heroX;2.1:quit"`. Workaround: none found in the game; the comment in `src/world.ts` names it (#16), and `tests/move.og.ts` asserts a smaller distance than the tuning would give.
17. **Two steps naming one output file overwrite each other without a warning** — nit. `get:Game:shop.json` then `dump_ui:shop.json` left only the dump, and the check failed far from the cause (`undefined is not an object`); it happened three times writing these tests. Repro: `og run examples/hollowbell --headless --commands "0.5:get:Game:x.json;0.5:dump_ui:x.json;0.6:quit"` (one x.json, no warning). Workaround: distinct names (`at-title.json`, `shopping.json`).
18. **With `store: "keep"`, an output named `platform.json` replaces the kept store** — nit. The store lives at `<out>/platform.json` (playtest.ts), and `dump_platform:platform.json` (the name lantern-vale's settings test uses) overwrote it, so the relaunch read an empty store. Repro: `dump_platform:platform.json` in `tests/save.og.ts`' first process. Workaround: `dump_platform:calls.json` (#18 in `tests/save.og.ts`).
19. **`get:` answers an enum field as its number** — nit. `get:music.og.AudioSource` answers `"bus": 1` where game code and the types have `"music"`. Repro: `og run examples/hollowbell --headless --commands "1:get:music.og.AudioSource.bus;1.1:quit"`. Workaround: the music test accepts either (#19 in `tests/music.og.ts`).
20. **The pixel style pack's primary button label is drawn in a shade of `accent`, not in `accentFg`** — annoyance. Resume, New game and Buy read dim olive on gold (og polish: 2.86:1 to 3.04:1, the only contrast findings left); setting `accentFg` (or `fgInverse`, `fg`, `bg`, `surface`, the body text shadow) to red changes no pixel of the label, setting `accent` green turns it green; the engine's own `crates/og-ui/references/metal/kit-skin-pixel.png` shows the same dim Resume, although og-taste §3 says the packs' test enforces every button label in every state at 4.5:1. Repro: `og polish examples/hollowbell` (`frames title: new "New game"`). Workaround: the accent lightened to `#f7dc74` and a 16 px type ramp (DotGothic16's own grid, so the one-pixel strokes stay whole) lifted it from 2.6–2.7:1; the rest is the pack's.

## What worked well

og cook: 69 assets cold in 3.6 s, incremental under 100 ms, no warnings; its refusals name the fix (a copied skin's missing CJK `fallback` named the line and og-taste §1; `PostEffects.vignette is true or false` named the line). The Tiled map with a blob47 auto-tiled terrain, Tiled's parallax and `repeat`, objects with properties, one-way planks on their own collision layer, flipbook frame events (`step`, `hit`, `toll`) driving footsteps, strikes and the bell, `og.physics.overlap` with sensors for the strike, `og.CameraZone` holding the arena, texture arrays as world sprites, screen sprites and emitter layers, the 2D glow, a game palette through `Stylise.palette` with a dither, `applyLook` to a second look at the results, `str` fields for the name and the save, the streamed music, `store: "keep"` relaunches and two-process replays each worked the first time they were asked correctly. The ui templates (main menu, pause, cutscene, shop, results with its localised Best and New best) and the text field with input-method composition needed no wiring. og polish found no locale gaps, every input answered within a tick, every damage moment with hit stop, shake, a number and a sound, and named the skill section for each finding.
