# What Rumpus Isle found

Every problem met writing this game from the knowledge package (skills and wiki) and the generated types as a game author would, in the order met. The observations below preserve the original round; the resolution table records the engine work done during recovery. Each game workaround is named, with the finding's number in the code. During authorship, engine source was not read except for the generated types and `packages/engine/src/node/polish.ts` (#13); the recovery inspected the owning CLI, physics and UI implementations and their tests. Ratings: **blocker** (the documented way does not work), **annoyance** (costs real time, or silently wrong), **nit** (small, cosmetic, docs only).

Begun on engine 20954c20, recovered on `dogfood-7` e8050670 with main ff952176 already merged, engine package pinned at 0.1.1. No one of these fourteen findings is fully fixed by that main revision: the 2D scaffold improvements do not fix #1's 3D look selection, and #10's panel inertness is intentional, not a newly introduced focus regression. The four original annoyances are not four proven runtime defects: #7 is missing renderer guidance, #9 combines missing timing guidance with an API gap, #10 is missing entrance/input guidance, and #14 is missing CLI selection.

The owner began the round on a rendering machine; recovery ran in an orb with `OG_RENDERER=none`. All eleven reference frames remain unchecked and `references/` is not recorded. The previous transcript supports inspection of only five lavapipe captures before a crash, with a subsequent capture run unfinished; the recovered claim that all eleven were inspected was unsupported and is withdrawn. No lavapipe run was repeated here. Commands below use the checkout's dev `target/debug/og` and addon, not registry binaries.

Top five: #9, #7, #10, #14, #3.

1. **`create --premise` picks a 2D flipbook look for a 3D party premise** — nit. `bun packages/create/bin/create.ts <dir> --premise "a local-multiplayer party game for two to four on one screen: round critters on a little island bump each other into the sea in short minigames; bright, bouncy, cartoon" --no-prompt` matched `rubber-hose-animation` (og-taste §12: "inked like early theatrical cartoons", a 2D style of flipbooks and squash) for a 3D profile it rightly chose; the preset's outlines and flat shading have nothing to say to spheres on a diorama. Repro: that command, then `grep extends <dir>/assets/looks/<id>.ogt`. Workaround: `extends "miniature-diorama"` by hand (#1 in `assets/looks/rumpus-isle.ogt`).
2. **No `Font()` field factory** — nit (API gap). og-core §4: "a handle wants a field of its own kind ... `Asset()`, `Texture()`, `Sound()`, `Geometry()`, `Material()` or `Entity()` (each handle type of the API has its factory)"; `og.load.font` answers a `Font` handle, and there is no `Font()` (nor `Skin()`), while `Asset` is "a loaded bundle, scene or glTF asset", so a `Font` is not one without a cast. Repro: `grep -n "function Font(" packages/engine/types/index.d.ts` (nothing). Workaround: the display font's handle for the name tags is an `f64` (#2 in `src/components.ts`, `Game.font`, cast back in `src/feel.ts`).
3. **Nothing in the skills points at `og.Camera.worldToScreen` for text over a world point** — nit (docs). og-ui §3 names screen text and world text and og-feel §7 floating text, but a name tag over a critter (screen text that follows a world point, under the UI) is in neither, and `Camera.worldToScreen` is only in the wiki's `camera.md` and the types, so the round's first draft projected by hand with the camera's pose and fov (the owner's, on the lane; it matched `worldToScreen` within 1e-5 px when found). World text (`og.render.text` without `screen`) is not the answer: it faces +z and rides the tone curve and the depth of field, so a tag reads tinted and soft at the frame's edge (seen on the lane's frames before the stop; the screen-text tags are crisp on the lavapipe frames of #7). Workaround: `cam.worldToScreen` and `screen: true` (#3 in `src/feel.ts`, `Tags`).
4. **A game command may not be named `pause`** — nit (docs). og-game §3 says commands are "snake_case actions"; `pause` is a core action of the channel (og-build §1) and the cook refuses it ("'pause' is a core action; register under another name", as Brasswick's round met), with no list of the names a game may not take in og-game. Workaround: `open_pause` (`src/main.ts`).
5. **The form of a command with two arguments is not written** — nit (docs). og-game §3 shows one argument (`0.5:spawn_wave:3`) and og-build §1's `usage` one (`<count>`); nothing says the arguments are the colon-separated fields after the name, so `records:12 34.5` was the first try (`bestBerries: got null`). Workaround: `records:12:34.5`, with `usage: "<berries>:<seconds>"` (`src/main.ts`, `tests/frames.og.ts`).
6. **Two steps at one time naming one file write `<name>-2.json`, and warn** — nit. og-build §1 says unnamed `get` answers on one tick go to `get-<tick>.json`, `get-<tick>-2.json`; two named steps at the same time with the same name (`0.5:get:Game:met.json` twice, a copy-paste) do the same, and the channel resolved it, but as a WARN ("'met.json' was already written by the 0.5s get step, so this one is 'met-2.json'; give each step its own file name"), which a playtest asserting a clean run (og-build §3) fails on. Workaround: distinct names.
7. **In a sandbox with no GPU but a Mesa lavapipe ICD, a headless `og run`, `og test` and `og polish` render every tick on the CPU: a 16 s playtest is minutes** — annoyance (docs). The original og-build §1 equated no GPU with tier `none`, but a software adapter still renders. The prior thread measured `og run . --headless`: `0.1:quit` 3.2 s, `1.0:quit` 17.4 s, the same with one `screenshot` 25.6 s, the frames playtest's 16 s script about 4 min at 1280x720; with `OG_RENDERER=none`, `1.0:quit` was 0.5 s. This was CPU rendering time, not a GPU-probe timeout. `og doctor` reported `renderer vulkan-cpu (a 64x64 frame headless in 843 ms)`. The switch was found in `docs/ci.md`, not the build skill. Workaround: `OG_RENDERER=none` for simulation checks; frames report unchecked. The coordinator must record and inspect the eleven retained metal references with `OG_FX_CAPTURE=1 og test examples/rumpus-isle` on the Mac. The interrupted lavapipe capture is not complete visual evidence (see the recovery note above). The engine should document headless rendering, the explicit opt-out and its visual-check limitation; fixed in the resolution table below.
8. **`get:<entity>.og.Transform` answers `position` as `[x, y, z]`; `set:` and `world.set` take `{x, y, z}` / `x,y,z`** — nit. A playtest reading a dump indexes an array where the code it mirrors reads fields. Workaround: the game's facts carry each seat's `x`, `y`, `z` (`src/main.ts`), and the playtests read those.
9. **`og.CollisionStarted` arrives the tick after the step, when `og.Velocity` already holds the contact's answer: a bump's closing speed read from it is never positive** — annoyance (docs, API gap). og-game §13 says contacts "arrive as events" and og.Velocity is "written for dynamic bodies every tick", and the event carries `point` and `normal` but no relative speed or impulse; a system reading the two bodies' `og.Velocity` on the event's tick sees them already parting (the solver's answer), so `max(0, closing)` was 0 on every bump in the round's first draft, every shove fell to its floor and no bump had hit stop, which `og polish` reported (hit feedback 83) and nothing else did. Repro: on 9f9c05f1, a `console.log` of `closing` in `Bumps` (`src/critters.ts`) and `og run examples/rumpus-isle --headless --commands "0.2:seat:wasd;0.3:seat:arrows;0.4:match;0.5:go;0.8:key_down:KeyA;0.8:key_down:ArrowRight;1.6:key_up:KeyA;1.6:key_up:ArrowRight;2.0:quit"` with `OG_RENDERER=none` (two critters driven head-on: `0.00` at every contact). Workaround: `Critter.vx`/`vz` keep the velocity `Drive` hands the step, and `Bumps` runs before `Drive` so it reads last tick's (9.23 m/s for the head-on above), with the event's `normal` for the line (#9 in `src/components.ts`, `src/critters.ts`, `src/main.ts`). The event could carry the relative velocity at contact, or og-game §13 could say what og.Velocity holds on the event's tick.
10. **A control that takes the focus after a screen transition takes it late: a press in the first 0.7 s is lost** — annoyance. og-ui §4: "What opens takes the focus"; after `title` (Escape from the lobby, an iris) the main menu's Play is built on the first tick of the title but answers Space only about 0.7 s after the transition begins, with no word on when, so a playtest's (or an eager player's) press at 0.6 s does nothing. Repro: in `tests/lobby.og.ts` move the `press("Space", 2.4)` after `press("Escape", 1.6)` to 2.2 (the title's phase is reached by 2.1, `title.json`). Workaround: the press at 2.4 s (#10 in `tests/lobby.og.ts`).
11. **An `f32` field widens in an og.platform payload** — nit. `records.crumble` written from a `f32(2.7)` arrives in `dump_platform` as `2.700000047683716`, so a playtest cannot compare the payload with the fact by `===`; og-platform-sdk §2 does not say the store keeps what JSON made of the float. Workaround: a tolerance (`tests/save.og.ts`).
12. **The iris keeps the previous screen on the surface for half a second** — nit (docs). og-ui §6 says to build the screen the transition answers; it does not say the old one stays until the iris closes (about 0.5 s), so a `dump_ui` right after a phase change lists the old screen's texts (the lobby after `match`, the title after `title`). Workaround: the dumps at +0.5–0.6 s (`tests/flow.og.ts`, `tests/locales.og.ts`).
13. **og polish asks for a floating number on every `hits` fact** — nit (og-build §5). A party game's bumps are hits (the measure needs a fact named so), but a number over each would be noise, and og-feel §7 itself says floating text is for "damage and score numbers"; hit feedback scores 100 on three signals of four, yet its fixes table lists "had no floating text within 8 ticks" for every bump of every playtest (three rows of the report's four), which a reader takes for work owed. The table could leave the fourth signal out where three are whole.
14. **`og test` runs every suite or none** — annoyance. `og test [project] [--json]` is the whole usage: nine playtests are 40 s a run (the first draft's, with the GPU probe of #7, an hour), and a loop on one suite reruns the eight others. og-build §4 names no filter. Workaround: `og run` with the suite's script by hand while iterating, `og test` at the end.

## Resolution and proposed engine work

The count above is the original encounter count, not an open-defect count.
Four findings are closed here (#7, #10, #12, #14); #9's documentation is
fixed but its impact-data API remains open. Nine other nits remain open.
All statuses below are against main ff952176 plus this branch's fixes.

| Finding | Status and what the engine should do |
|---|---|
| #1 `create --premise` | Open. Make look selection aware of the chosen 2D/3D profile and catalogue suitability, so a 3D party premise does not rank a flipbook-only style first. Preserve an explicit `--look` override. Main's 2D scaffold work does not resolve this. |
| #2 `Font()` / `Skin()` | Open. Supply typed field factories for every public handle kind, with generated declarations and runtime exports together; test round-tripping handles through component fields. Do not make authors cast a font to an unrelated `Asset`. |
| #3 `Camera.worldToScreen` | Open. Add the world-point-to-screen-text name-tag pattern to og-ui §3 and link it from og-feel; explain that screen text avoids world lighting and depth of field. |
| #4 `GameDesc.commands` | Open. Link the reserved core-action list from og-game §3 and show `open_pause` as the game action distinct from the engine's `pause`. Keep the cook's collision refusal. |
| #5 command arguments | Open. Show `records:12:34.5`, `args[0]` / `args[1]` and `usage: "<berries>:<seconds>"` together in og-game and og-build; arguments are colon-delimited, not shell words. |
| #6 duplicate output names | Open documentation nit, not a data-loss defect. Keep the warning that catches an accidental duplicate; document named-output suffixing and its effect on clean-warning assertions. The existing advice to give steps distinct names is already on main, but not the named-collision contract. |
| #7 headless rendering | **Fixed by [baf28bfe](https://github.com/originai-game/origin-engine/commit/baf28bfe)**: og-build §1 names lavapipe, says headless still renders, gives `OG_RENDERER=none` and explicitly withholds visual approval. No automatic renderer downgrade was added. |
| #8 transform dumps | Open. Document vector arrays in command-channel JSON beside the API's vector objects and `set`'s comma syntax, with a dump-reading example. Do not silently change the existing dump format. |
| #9 `CollisionStarted` | **Documentation fixed by [baf28bfe](https://github.com/originai-game/origin-engine/commit/baf28bfe)**: og-game §13 explains next-tick delivery, post-solver velocities, and the cache workaround's limits. **API still open.** Add contact-time relative velocity (including angular point velocity) or solver impulse with defined units and `a`-to-`b` orientation, implemented in both 2D/3D backends and reflected through the IDL and both hosts. Test asymmetric impacts, rotation, static/kinematic bodies, and snapshot/replay. This is not a contained one-crate patch: it changes the public event schema and both backends; a cached pre-step centre velocity would not fulfil that contract. |
| #10 transition input | **Documentation fixed by [baf28bfe](https://github.com/originai-game/origin-engine/commit/baf28bfe)**. `og-ui/src/widgets.rs::enter` deliberately makes an entering panel inert; `og-ui/tests/skin.rs` asserts early presses are rejected and `instant` responds immediately. This is panel input suppression, not merely late focus. og-ui §4 now describes it, with `instant: true` for immediate interaction; no blanket input buffering or runtime timing change. |
| #11 `f32` payload | Open documentation nit. Explain IEEE-754 single precision promoted to a JSON number, recommend tolerance for numeric tests and explicit rounding only for display. The store should preserve the supplied number, not round it silently. |
| #12 iris old screen | **Fixed by [baf28bfe](https://github.com/originai-game/origin-engine/commit/baf28bfe)**: og-ui §6 states the half-duration switch and distinguishes the cover from the new panel's entrance. |
| #13 polish feedback | Open. Align the fixes table with the three-of-four hit-feedback rule: suppress an optional fourth signal when three are present for that impact, rather than recommending floating numbers on every party-game bump. Cover both satisfied and deficient impacts in a package test. |
| #14 suite selection | **Fixed by [8dfd2416](https://github.com/originai-game/origin-engine/commit/8dfd2416)**: `og test . --filter tests/lobby.og.ts`; case-sensitive substring of project-relative paths, for both `.og.ts` and `.test.ts`, with the normal type check retained. No match fails. Help and og-build document it; a CLI regression fails on the old code and checks selected suites, excluded failing suites, nested paths, missing arguments and no-match failures. |

## Recovery verification (2026-10-22)

```sh
bun tools/make-assets.ts
OG_RENDERER=none ../../target/debug/og cook .
OG_RENDERER=none ../../target/debug/og check .
OG_RENDERER=none ../../target/debug/og test .
OG_RENDERER=none ../../target/debug/og polish .
```

- Asset generation succeeded without tracked asset drift; cook: 40 assets,
  47 outputs, all 47 cooked. Check: ok (tsrs).
- Full game test: 9 suites, 216 checks passed; **11 frames unchecked**.
  Filtered run after the CLI change: lobby alone, 16 checks passed.
- Polish: taste 100, feel 93, 3 findings (the floating-text advice in #13).
  These scores with no renderer do not verify appearance.
- `cargo check -p og-cli` and `cargo test -p og-cli`: pass (8 unit tests,
  21 CLI integration tests). The new regression first failed with
  `unknown option --filter` on the old implementation.
- `bun run --cwd packages/knowledge validate`: pass. No gate, wasm build,
  browser run or lavapipe reference capture was run in this stream.
- The orb had no gate wasm cache. `OG_GATE=1 packages/engine/scripts/build.sh`
  would fall through to wasm compilation, so its native portion was run
  directly: `PATH="$HOME/.cargo/bin:$PATH" cargo build -p og-host-node -p og-cli`,
  then the dev CLI and addon copied into `packages/engine/native/` with
  `build-profile` set to `dev`. No release build or registry engine was used.

behaviour was changed in this recovery.

## What worked well

og cook: 40 assets with no warnings, three glTF models from a script (`tools/glb.ts`) with their materials, a 30 s stereo music streamed in chunks, og sfx presets for every sound, the cartoon skin pack copied and recoloured. Dynamic sphere critters with locked rotation about x and z, damping and no gravity drove, dashed, bumped (`og.physics.applyImpulse`, a squash each) and fell into `og.Water` with an `og.WaterSurface` that splashed; a kinematic island sank under a grid of kinematic tiles that cracked and dropped one by one, and three kinematic boxes made the podium's steps ground (an instantiated glTF has no collider, as og-game §13 shows: one is inserted). Six input sources on one world, four pads and two halves of the keyboard, sat down in a lobby where every pad has its own focus ring (`og.ui.setPlayers`) and the keys pick colours with left and right; `og.ui.screenTransition`'s iris between every screen, `og.ui.settingsScreen` every word in French from the tables (spaces before `?` and `!`, accents from the cartoon pack's faces), `og.ui.mainMenu` and `og.ui.pauseMenu` with their Back, count-ups and bursts on the scoreboard. og.platform kept the settings and the isle's records across a relaunch at the revision read, with a conflict merged by the best of each; a match by the keys alone from the title through two rounds ended on one hash in two processes; `og.time.hitStop` and `og.time.setScale` froze the critters and not the UI. The playtests: nine suites, 216 checks, 40 s together with no renderer.
