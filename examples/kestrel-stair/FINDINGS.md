# What The Kestrel Stair found

Every problem met writing this game from the knowledge package (skills and wiki) and the generated types as a game author would, in the order met. Nothing in the engine was changed; each workaround is named, and the code carries it with a comment naming the finding's number. Engine source was read only to confirm a suspected bug after it was hit (#7, #10, #12, #19 say so). Ratings: **blocker** (the documented way does not work), **annoyance** (costs real time, or silently wrong), **nit** (small, cosmetic, docs only). Engine e16e9cec (main after wave 9, so Lantern Vale's and Hollowbell's findings fixed there are not repeated), then main f1a31849 (wave 10) merged at the end, where every finding below was checked again: #16 and #17 were fixed by wave 10's character mover and #18 by its template words, which this game then took up; the rest stand. Dev-profile `og` and addon; tier metal. Commands run from the repository root, `og` = `target/debug/og`.

Top five: #7, #10, #19, #13, #6 (with #2).

1. **No skill names a pattern for a 3D action game** — nit (docs). og-game §8 and §9, og-feel §12 and og-ai §5 point at the topdown, runner, match3, roguelike, tower-defense, idle and rhythm archetypes and fx-showcase's stations; `templates/archetypes/third-person` (a controller over a level, clips retargeted at cook and at run time, blend trees, a navmesh, behaviour machines with game commands) is named once, as a folder of particle files (og-game §10). Repro: `grep -rn "third-person" packages/knowledge` (that one line, and og.FollowCamera's doc). Workaround: found by listing `templates/archetypes/`; read for the grammars of #2 only.
2. **Three grammars the game needs are outside the knowledge package** — annoyance (docs). A navmesh `.ogt`: og-ai §1 names its parts ("the agent (radius, height, climb, slope), the cell and tile sizes, the bounds and the geometry (`box`, `scene` or `model` entries)") but no line of it; wiki/ai.md says the behaviour grammar is `crates/og-ai/README.md` (og-ai §3 shows a tree, and a machine only as `machine { initial idle; state idle { ...; to alert { check heard } } }`, without `enter`, `after`, `stop`, `move_to`, `reach`); `GraphDesc.text` says the animgraph grammar is "og-anim's README" (og-game §9 points at fx-showcase's walker). Repro: `grep -rln "blend1d" packages/knowledge` (nothing) and `grep -rn "climb" packages/knowledge/skills packages/knowledge/wiki/nav.md` (og-ai §1's one row is all there is of the navmesh file; og-game's hits are the controllers'). Workaround: the third-person archetype's `assets/nav/vale.ogt`, `src/anim.ts` and `assets/ai/sentinel-west.ogt`, and a guessed `model "models/stair.glb" { position 0 0 0 }` the cook took (#2 in `tools/level.ts`, `src/anim.ts`).
3. **A behaviour's `check` takes only a literal, while og-ai §3 says tune numbers live in components and resources, never as copies in the .ogt** — annoyance. `check Foe.hp below Tuning.impFleeHp` and `check targetDistance below Tuning.wardenReach` are refused by the cook (`'check' needs a value: a number, three numbers (a point) or true/false`), though actions take `speed Tuning.slimeSpeed`. Repro: write `check targetDistance below Tuning.sight` in any `examples/kestrel-stair/assets/ai/*.ogt`, then `og cook examples/kestrel-stair`. Workaround: the generator writes the thresholds from one table (`MIND` in `src/layout.ts`) into the behaviours, and the game reads the same table (#3 in `src/layout.ts`, `tools/level.ts`).
4. **`og.tween.squash`'s impact is a Vector2 in the 3D profile** — nit. `SquashDesc.impact` is x and y only (its doc and og-feel §5 are written for sprites), so a 3D model's squash leaves z at rest; the types refuse `{ x, y, z }`. Repro: `impact: { x: 1.1, y: 0.9, z: 1.1 }` in `examples/kestrel-stair/src/hero.ts`, then `bun run typecheck` there. Workaround: x and y only (#4 in `src/foes.ts`). **Fixed in wave 11** (physics-anim-2): `SquashDesc.impact` is a `Partial<Vector3>`; z scales a 3D model and, left out or 0, stays at rest (og-feel §5); the courier's and the foes' squashes give z.
5. **There is no way to restart an agent's behaviour** — nit (API gap). og.AiAgent starts a machine afresh only when its `behaviour` handle changes; a new run must put every warden back in `patrol`, so each behaviour is loaded twice and the handles swapped (the third-person archetype's trick, in its code, not in og-ai). Repro: `grep -rn "restart\|afresh" packages/knowledge` (nothing about agents). Workaround: `Foe.mind` and `Foe.spare` swapped in `reset` (#5 in `src/foes.ts`).
6. **Inside a system, `world.get`/`world.set` refuse on every entity its declared components match, even when the system takes no view; whether a system can touch a named entity depends on whether its reads and writes happen to match one** — annoyance. A View system declaring `writes: [og.Camera, og.Transform]` to move the audio listener failed on its first tick: `'og.Transform' is borrowed by the running code (a column or resource view is still held)`, though the code held none. og-core §4 says a written component is borrowed by its views, not that the declaration takes the borrow for every matched archetype; Lantern Vale's and the archetype's per-entity systems work only because their many components match no entity. Repro: remove `OneByOne` from View's reads in `examples/kestrel-stair/src/view.ts`, then `og run examples/kestrel-stair --headless --commands "0.5:quit"`. Workaround: a component no entity has (`OneByOne`) in the reads of every system that works one entity at a time, so its query matches nothing (#6 in `src/components.ts`).
7. **BLOCKER: an og.NavAgent that has not planned is moved from navmesh polygon 0, whatever its height, and is then off the navmesh for good.** Every idle agent (seeking false, the default; og-ai §2's example inserts one so) jumps on its first tick to y 8.1, the height of a polygon on the high terrace, wherever it stands: the court's imps at y 0 and the crypt terrace's warden at y 4 alike; then `status` is `NAV_UNREACHABLE` for ever, so a behaviour that starts with `wait` (a patrol at its first point) never moves. Confirmed after hitting it: `PathState` derives `Default` (`crates/og-nav/src/system.rs`), so a new agent's `poly` is 0, a valid polygon, and the idle branch calls `move_along` from it. Repro: in `examples/kestrel-stair/src/foes.ts` give the spawned and the reset NavAgents `seeking: false` and the home target, and never wake the AiAgent (`if (false)` for the wake), then `og run examples/kestrel-stair --headless --commands "0.017:get:imp-0.og.Transform.position;0.017:get:warden-0.og.Transform.position;0.1:quit"`: `[-9.0001, 8.1, 31]` and `[5.9999, 8.1, -2]`. Workaround: every agent is placed seeking its round's next point with its mind off, and its AiAgent is woken only once `NavAgent.plans` has grown (#7 in `src/foes.ts`, `Foe.warm` in `src/components.ts`). Still so on main f1a31849.
8. **og.Perception hears its own agent's sounds** — nit. An imp carries its spatial chitter (og-audio §6), and it hears it: its blackboard's `heardAt` is where it stood on its second tick (-8.995, 0.1, 31) and `sinceHeard` counts from then, with no other sound near; a behaviour checking `heard` would react to itself every time its loop starts. Repro: `og run examples/kestrel-stair --headless --commands "1:dump_ai:imp-0:ai.json;1.1:quit"` (`heardAt`, `sinceHeard` 0.95). Workaround: none needed here (the minds do not check `heard`).
9. **`NavMeshInfo`'s bounds are wrong** — nit. `og.nav.load(world, "nav/stair.ogt")` answers `min` (-23, -1.1, -67) and `max` (23, 1.5, 45) for a navmesh whose bounds reach y 14 and which has polygons at y 12 (`og.nav.nearest` finds (0, 12.1, -60)). Repro: a command that throws `JSON.stringify(must(og.nav.load(world, "nav/stair.ogt")))`, run with `0.2:<command>;0.3:quit`. Workaround: none needed (unused).
10. **A cloth or rope reads its entity's own Transform as world space: on a child entity it hangs at the world's origin** — annoyance (bug). The cape, a child of the courier's body at the shoulders as og-game §13 ("a cape on the ground") and og.Cloth's doc ("pinned points follow the entity") invite, hung near (0.24, 1.52, -0.2) while the courier stood at z 39 (`og.physics.clothPoints`). Confirmed after hitting it: `crates/og-physics/src/gather.rs` `placed!` reads `Transform.position` and `quaternion` for ropes, cloths, fluids, water lines and ragdolls, not `MatrixWorld`. Repro: spawn `hero-cape` with `parent: body` and drop its per-tick placement in `examples/kestrel-stair/src/hero.ts`, then `og run examples/kestrel-stair --headless --commands "0.3:play:0:quick;1:screenshot:cape.png;1.1:quit"` (no cape on the courier). Workaround: an unparented cape entity that HeroMove places at the shoulders every tick, held or not (#10 in `src/hero.ts`). Still so on main. **Fixed in wave 11** (physics-anim-2): ropes, cloths, fluids, water and ragdolls are placed at their entity's world pose down the og.Parent chain (`og_physics::world_pose`); the cape is a child of the body again and HeroMove no longer places it.
11. **A glTF character cannot take a hit flash** — annoyance (API gap). og-feel §3 pairs a hit stop with `og.tween.flash`, which takes an `og.Sprite` or an `og.Mesh`; an instantiated glTF draws through `og.Model` (`entity … has neither og.Sprite nor og.Mesh`), and its materials (`GltfInfo.materials`) are shared by every instance, so one imp cannot flash alone. Repro: `og.tween.flash(world, { entity: world.find("imp-0")!, amount: 1 })` in a command (refused). Workaround: the struck foe flinches (a squash, #4) and sparks fly (#11 in `src/foes.ts`, `tests/combat.og.ts`).
12. **How a glTF clip carries its markers is not in the knowledge package** — annoyance (docs). `og.AnimationEvent` reports "a clip's named frames" (og-game §9) and `ClipInfo.markers` lists them, but nothing says how to author one; `extras.markers` came out empty. Found in `crates/og-cook/README.md` after the markers were missing: `animations[i].extras."og.events"` (`[{ "name", "time" }]`) or `animation { event "<clip>" "<name>" <s> }` in the import settings. Repro: `grep -rn "og.events" packages/knowledge` (nothing). Workaround: `tools/rig.ts` writes `extras."og.events"`; strikes, bites and slams land on the `hit` marker.
13. **A mid-size 3D world's `world.snapshot()` is over the store's 64 KiB a key** — annoyance. og-game §17 and og-core §2 show the snapshot put in one store key beside the slot's summary; this world (93 entities: five skinned characters on graphs, five cloths and a rope, five navmesh agents with minds) is about 77 KB of text (Hollowbell's 25 KiB is the only size given), and `storeSet` refuses it at the call with only a `Result` to say so. Repro: `og run examples/kestrel-stair --headless --commands "0.3:play:0:quick;0.6:warp:waystone-1;0.9:key_down:KeyF;0.934:key_up:KeyF;1.2:get:Game.saveBytes;1.3:quit"` (78,000-odd). Workaround: the text in parts of 60,000 characters (`slot.0`, `slot.1`) and `slot` holding the place, the hour and the count, written last; Continue reads every part before `world.restore` (#13 in `src/save.ts`, `tests/save.og.ts`).
14. **The title menu takes no focus, so Enter and the pad's A do nothing on it until an arrow or Tab** — annoyance. og-ui §4: "What opens takes the focus: a dialog … its first control, a dialogue box or cutscene the box"; `og.ui.mainMenu` is neither, and a keyboard or pad player's first press at the title is lost. `og.ui.navigate` applies on the tick after it is queued, so focusing it while `og.ui.focus(0)` is empty queues two and lands on the second item. Repro: drop the `navigate` lines in `examples/kestrel-stair/src/ui.ts`, then `og run examples/kestrel-stair --headless --commands "1:key_down:Enter;1.034:key_up:Enter;1.3:get:Game.phase;1.4:quit"` (0). Workaround: the title's first item focused when nothing is, asked once and not again for three ticks (#14 in `src/ui.ts`, `Game.focusAsked`).
15. **`og.ui.levelSelect` ignores `columns` and draws a level's name in display type on a 104 px card, cut off** — annoyance. With `columns: 2` (and 1) the four chapters stand in one row of 104 px squares; "I · The Lower Court" is a 173 px label clipped to "e Lower C". `og.ui.inventoryScreen`'s `columns: 6` also lays out five. Repro: name a chapter `"The Lower Court"` in `examples/kestrel-stair/assets/strings/en.ogt`, cook, then `og run examples/kestrel-stair --headless --commands "0.5:open:chapters;1.6:screenshot:ch.png;1.7:quit"`. Workaround: the chapters are numerals on their cards (#15 in `src/ui.ts`).
16. **`og.CharacterController.sliding` read true standing on level ground** — nit. Fixed on main by wave 10's mover (876dd4ea, row 72), confirmed after the merge; met at e16e9cec: `grounded` true, `groundNormal` (0, 1, 0), `sliding` true, walking and standing on the court and a ledge.
17. **On stairs the 3D controller stuttered and on slopes it lost speed** — annoyance. Fixed on main by wave 10's mover (876dd4ea, row 72), confirmed after the merge (3.2 m/s every tick on the court, the ramp, the steep path and the stairs). Met at e16e9cec with `Tuning.walkSpeed` 3.2: up the stairs the per-tick speed ran 3.2, 1.4, 0.39, 0.8, 1.06, 3.2, … (2.1 m/s on average), the 34° path 2.14 and the 18° ramp 2.83 m/s across the ground; the move playtest's timings were written for it and kept.
18. **The cutscene's, tutorial's, bag's and leaderboard's own words had no desc field** — annoyance, already row 76 when met. Met at e16e9cec in Japanese: Skip, Next, "1 of 4", the bag's hint and Count stayed English. Fixed on main by wave 10 (77cb5b0a); after the merge the game passes `CutsceneDesc.skipLabel`, `TutorialDesc.skipLabel`/`nextLabel`/`doneLabel`/`stepLabel`, `InventoryDesc.hintLabel`/`countLabel` and `LeaderboardDesc.retryLabel` from its tables, and `tests/locales.og.ts` asserts no English word is left.
19. **A resource's field write costs in proportion to the whole resource, and so does the next read** — annoyance (perf). Each setter is one engine call writing `{ field: value }` as JSON, and the following read fetches and parses the whole record (`packages/engine/src/runtime.ts` `liveResource`, read after hitting it): with `Game` (130 fields, two `str`) a write took about 0.1 ms and `world.resource(Game)` 0.16–0.23 ms (Prefs, 11 fields: 0.01 and 0.02 ms). Kept the way og-core §4 and og-game §3 show (one run resource, systems writing its fields), the game spent most of a tick there: 34 ms a tick in `og run --json`, the Foes system alone about 16 ms. Repro: a command timing 200 writes of `g.heroX` with `performance.now()`. Workaround: each system reads Game once into a plain copy and writes back only the fields that changed (`src/state.ts`, #19), per-entity calls made only on a change: 14 ms a tick, step about 7.5 ms median in og polish. The rest is the frame time og polish scores 0 to 9 here (frame p95 11–36 ms between runs on a machine shared with other builds; step 6–10 ms median, 9–30 ms p95, render 2.2 ms).
20. **The paper pack's leaderboard and bag measure under 4.5:1** — nit. og polish: the player's rank on its highlighted row 3.31:1 (the medal ink), a stack's count in the bag 3.3–3.5:1 (a darker `fgSubtle` changed nothing) and "You" on that row 2.14:1, though its glyph cores reach about 12:1 in the frame: a three-letter name in a 356 px wide label leaves the 1 % farthest pixels mostly antialiased edges (og-build §5 says the ink is the 1 % farthest pixels; a short text in a wide element is not mentioned). Repro: `og polish examples/kestrel-stair` (`win records`, `bag bag`). Workaround: none in the game (the templates' rows and slots take their inks from the pack).
21. **There is no reverb zone** — nit (API gap). og-audio §4 and §6 give one shared reverb fed by each bus's send (`AudioBusFx.reverb`, `og.Audio.reverbRoom`); a room that sounds like a room is game code. Workaround: the Fx system eases the effects bus's send, the room size and the damping (and the sky's light) while the courier's head is in the crypt's box (#21 in `src/fx.ts`, `tests/audio.og.ts`).

## What worked well

og cook: 62 assets cold in 8.5 s (110 outputs, 9.9 MB), about 0.1 s after a change, no warnings; a navmesh baked from the level's glTF with a guessed `model` line, the clip library retargeted onto a Mixamo-named, A-posed character at cook time, and its refusals (#3) named the line. At run time `og.anim.retarget` took the same clips onto an Unreal-named imp (bones detected) and onto a warden whose bones only a `type rig` file names, and all three played through blend trees the first time; `hit` markers came through both retargets; a warden's slam lunged 1.0 m by root motion with `Skeleton.rootMotion` switched to planar for its length. Behaviour trees and machines (patrol, chase with a wind-up, bite, flee; alert, slam, search) with the game's commands, sight occluded by the level, `og.Steering` separation and avoidance, `og.nav.setObstacle` for the gate. The character controller over triangle meshes (slopes, the scree refused, steps, ledges; after wave 10 at full speed on every one of them). Spatial sources with distance, pan, distance dulling and occlusion, read back exactly through `og.AudioPlayback`; chunked music. `world.snapshot()`/`world.restore()` across a relaunch, bringing back 93 entities with their cloth, nav and minds. Every template asked for (cutscene, tutorial overlay, inventory with drag and drop, level select, leaderboard with honest states, settings, results, pause) worked from its desc, the paper pack restyled them all, and the Japanese subset from the ui-kit's script needed no other step. Two processes of a full session end on one hash; og polish found every input answered within a tick and every damage moment with hit stop, shake, a number and a sound.
