# Spike results — 2026-10-17

The go/no-go measurements of `docs/design.md` §10, taken on one machine
(MacBook Pro, Apple M4 Pro, macOS, 120 Hz display) with Chrome for Testing
150 headless (`--disable-gpu-vsync --disable-frame-rate-limit`, ANGLE Metal),
and in the platform's current E2B `probe` sandbox (2 vCPU, Mesa lavapipe
25, no GPU). The mobile numbers (iPhone first frame, mid-range Android
system cost) are **not taken yet**: they need the devices.

## What the spike is

`og-spike` renders a reference scene with wgpu: PBR metallic-roughness with
textures, one directional light with a 2048² shadow map and 3×3 PCF, split-sum
IBL from a procedural sky (irradiance, prefiltered specular mips, BRDF LUT,
all generated by render passes), ACES tonemapping. The same crate runs:

- natively, headless, writing a PNG (`og-spike --out frame.png model.glb…`),
- as `og_spike_bg.wasm` in a Worker on an OffscreenCanvas (`web/`), on
  WebGPU or on WebGL2 through wgpu's GL backend.

Two scenes: `gltf` = `count` instances each of `trickster.glb` (20.6k
vertices, textured, 1 material) and `dropship.glb` (17k vertices, 16
materials) on a checker ground; `sphere` = `count` low-poly spheres (384
triangles) whose matrices are rotated on the CPU and re-uploaded every frame.
`web/compare.html` builds the same scenes in three.js 0.180 (instanced, or
one `Mesh` per object with `naive=1`).

## 1. Size

| Artifact | Bytes |
|---|---|
| `og_spike_bg.wasm` after `wasm-opt -Oz` | 3,190,709 |
| brotli -q 11 | **911,473** |
| gzip -9 | 1,234,131 |
| native Linux x86_64 binary (static, zigbuild glibc 2.31) | 6,864,856 |

Budget: ≤ 4 MB brotli for the core. The spike is a renderer only (no
physics, animation, audio, UI), so the budget is not yet exercised, but the
baseline leaves 3 MB for the rest.

## 2. Same frame, native and sandbox

| Where | Adapter | Setup | Frame (880k triangles, 1280×720) |
|---|---|---|---|
| macOS native | Apple M4 Pro, Metal | 0.3 s | 1.4–1.5 ms |
| E2B `probe` sandbox | llvmpipe (LLVM 15, 2 vCPU), Vulkan | 1.1 s | 236 ms |

The sandbox frame and the native frame at the same tick differ by RMSE
0.0027 (`magick compare`): the executor path produces the same picture as
the player's GPU, headless, with no browser and no Godot in the image. The
sandbox binary was uploaded into today's `origin-runner-probe` template and
run with `VK_ICD_FILENAMES` pointing at lavapipe; nothing else was needed.

## 3. Browser frame times (p50 of the rAF interval, ms; lower is better)

glTF scene, instanced on both sides (GPU-bound):

| count per model | triangles | spike WebGPU | spike WebGL2 | three WebGL2 (InstancedMesh) | three WebGPU (InstancedMesh) |
|---|---|---|---|---|---|
| 100 | 3.5 M | 3.27 | 4.25 | 3.53 | 2.79 |
| 200 | 7.0 M | 5.97 | — | 6.61 | — |

Moving sphere field, every matrix updated and uploaded per frame:

| objects | spike WebGPU | spike WebGL2 | three WebGL2 instanced | three WebGL2 one Mesh each | three WebGPU one Mesh each |
|---|---|---|---|---|---|
| 5,000 | 1.60 | 2.79 | 2.43 | 7.38 (5,001 draws) | 35.4 |
| 20,000 | 4.58 | 6.54 | 4.00 | 34.4 (20,001 draws) | — |

First frame on this machine: 65–150 ms for the spike (wasm init 5–15 ms,
renderer setup 45–140 ms, dominated by IBL generation and pipeline
compilation); 70–560 ms for three.js (PMREM and shader compilation).

Reading:

- **GPU-bound scenes are parity.** With both sides instanced, the spike and
  three.js land within ±20 % of each other at 3.5–7 M triangles; three's
  WebGPU renderer is slightly faster than the spike on the glTF scene. The
  renderer architecture does not change raster throughput, and the spike's
  fragment shader (explicit PCF, IBL) is if anything heavier than three's.
- **CPU-bound scenes are where the engine wins, by construction.** The
  spike draws 20,000 moving objects in 5 draw calls at 4.6 ms; three.js with
  one `Mesh` per object, which is what hand-written and model-written
  three.js games do, takes 34 ms (7.5×). three.js *can* match the spike with
  `InstancedMesh` written by hand (4.0 ms), so the claim is not "faster than
  three.js", it is "batched and instanced by default, so the author cannot
  write the slow version".
- **WebGL2 fallback costs about 30–45 %** on the same scenes and works
  through the same code (shadows read from an R32Float target with explicit
  compares, since WebGL2 cannot filter or `textureLod` a depth texture).

Against §10's branches: the 1.5× threshold is not met for instanced GPU-bound
content and is exceeded by 7× for per-object content. The positioning the
numbers support is the second sentence above, not a raw-speed claim.

## 4. TypeScript systems over typed views (§10.3)

`bench/views.ts`, one `WebAssembly.Memory` holding SoA columns, a system
written as a loop over `Float32Array` views:

| entities | integrate (ms/tick) | integrate + branchy damage system | per-entity accessor objects (the anti-pattern) |
|---|---|---|---|
| 10,000 (bun 1.4) | 0.014 | 0.016 | 0.28 |
| 10,000 (node 26) | 0.016 | 0.029 | 3.05 |
| 100,000 (bun) | 0.114 | 0.158 | 2.89 |

Budget: ≤ 1.0 ms per tick for 10,000 entities on a 2022 mid-range Android.
Desktop is 60–70× under it; a 10× slower phone still has 6× headroom. The
accessor anti-pattern is 20–200× slower and is what the API must not offer.

## Reproduce

```sh
cargo build --release && ./target/release/og-spike --out frame.png --count 25 web/models/trickster.glb web/models/dropship.glb
./target/release/og-spike --out spheres.png --sphere --moving --count 5000
cargo build --release --target wasm32-unknown-unknown -p og-spike --lib && wasm-bindgen --target web --out-dir web/pkg --no-typescript target/wasm32-unknown-unknown/release/og_spike.wasm && wasm-opt -Oz --enable-bulk-memory --enable-nontrapping-float-to-int -o web/pkg/og_spike_bg.wasm web/pkg/og_spike_bg.wasm
cd web && bun serve.ts &                      # COOP/COEP static server with a /result sink
./run-chrome.sh "http://127.0.0.1:4173/index.html?count=100&seconds=6" 16          # spike, WebGPU
./run-chrome.sh "http://127.0.0.1:4173/index.html?count=100&seconds=6&webgl=1" 16  # spike, WebGL2
./run-chrome.sh "http://127.0.0.1:4173/compare.html?count=100&seconds=6" 16        # three.js
bun bench/views.ts 10000
cargo zigbuild --release --target x86_64-unknown-linux-gnu.2.31 -p og-spike --bin og-spike && bun web/e2b-run.ts   # sandbox frame (billable)
```
